## 2. What is broken?

1. **Publication dates are corrupted site-wide (the known critical bug).** Details in §5–§6. Posts show 2024-09 → 2025-05 dates that contradict their own embedded evidence (comment dates, image upload paths, in-text date references).
2. **Positioning mismatch.** The live site title/branding says «طراح و پژوهشگر – Designer & Researcher» and lists 7 generic services (web/app development, digital marketing…) — exactly the "generic agency" pattern the new brand strategy forbids.
3. **Tag pollution:** 4,872 tags vs 83 posts destroys taxonomy quality and creates thousands of thin/duplicate archive URLs (SEO negative).
4. **Duplicate taxonomy:** two `تکنولوژی` categories, `کسب و کار` vs `کسب‌وکار`, `دسته‌بندی نشده` variants.
5. **No meta description on the homepage.** Title contains decorative `☼` characters.
6. **No real sitemap strategy:** only WP core `wp-sitemap.xml`; tag sitemaps ship thousands of junk URLs.
7. **Mixed slug quality:** most post slugs are long percent-encoded Persian strings (e.g. `/فرصت-های-سرمایه-گذاری…` encoded), recent posts (2025-10+) use clean English slugs (`iran-railway-technology-startup`, `bizpal-digital-sales-marketing-and-advertising-startup`).
8. **Date anomaly on a page:** `invest-startup` page dated **2026-02-16** (created recently, fine) but content is empty in the API (Elementor-built).
9. **Media hygiene:** ~48% of media lack alt text; theme-demo junk media exists (e.g. `hoodie_6_front.jpg` from 2013, `inner_page_4.png` from 2019 — demo assets, not content).

### What is NOT broken
- Comment records preserve original dates (this is what lets us repair post dates).
- Media upload paths preserve original year/month.
- Content bodies are intact (median 5.7 KB HTML, max 77 KB; long-form 2,000+ word Persian articles).
- The 17 comments are all approved, threaded, and look legitimate (including replies by Mehrdad).

## 6. Where can date corruption occur (in the new system)?

| Corruption vector | Prevention in new architecture |
|---|---|
| Migration script using row-insert time as publish time | Content model separates `publishedAt` / `updatedAt` / `migratedAt`; seed sets `publishedAt` ONLY from evidence chain |
| CMS auto-stamping "new" imported posts | `publishedAt` is an immutable, explicitly-provided field; migration report lists every date + evidence |
| Random back-dating "to look realistic" | **Forbidden.** Date evidence table per post: source = `wp-date` (if consistent) / `comment-bound` / `upload-path` / `self-reference` / `unknown-approximate`. Unknown → `datePrecision` field = `day` / `month` / `year` / `unknown` |
| Sorting UI hiding imprecision | UI renders «مهر ۱۴۰۲» style when precision=month, «حدود ۲۰۲۱» when approximate |

## 14. Migration plan (Phase 2 in detail)

1. **Extract** full WP payloads (posts w/ content, comments, media list, categories) — already cached in audit workspace; script re-fetches authoritatively.
2. **Date reconstruction algorithm** (per post, evidence priority order):
   1. Comment-date lower bound (min comment date on post) — if no contradiction, adopt month precision around it;
   2. Upload-path YYYY/MM of images embedded in that post;
   3. In-content self-dated references (1400-era Clubhouse texts → 2021);
   4. If WP `date` is consistent with all above → keep it;
   5. Else set best-evidence date with `datePrecision=month` (or `year`), never silently;
   6. Wayback Machine snapshot check when network allows (upper bound).
   Every decision lands in `docs/MIGRATION_REPORT.md` with per-post evidence.
3. **Slug policy:** keep original slugs byte-for-byte; for the new pretty routes use same slug (Unicode URLs supported) → most posts need **no redirect**; any slug normalization → 301 row.
4. **Sanitize HTML:** whitelist tags, strip Elementor wrappers/inline styles, keep `<img>` with local mirroring, keep internal links (rewrite old→new), preserve `<blockquote>/<table>/<ul>`.
5. **Media mirror:** download images referenced by posts → `public/media/YYYY/MM/…` mirroring original paths; record mapping; add 301 for `/wp-content/uploads/*`.
6. **Comments:** import with original `submittedAt`, thread parents, approved flag (2 suspicious → unapproved).
7. **Validation gates:** count checks (82/82 bodies, 17/17 comments), no empty bodies, no future dates, no dates newer than evidence allows, media 404 scan, redirect-map completeness → report committed to GitHub.
8. **Owner flags:** password-protected post 7995, «cannabis michigan» comment, 4 neobank posts diff → documented decisions, not silent choices.
